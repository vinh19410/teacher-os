# Issue 125 staging auth silent fail — PWA service worker root cause

QC P0: staging signup/sign-in failed silent (no toast, get-session null). Live investigation proved the API/auth layer healthy (curl round-trip, CORS, Set-Cookie correct; app/api.staging same-site via PSL io.vn) and pinned the root cause on the vite-plugin-pwa service worker: with the SW active a real browser booted the SPA blank (#app empty) and module imports failed at network level; after unregister + cache clear the same deploy rendered and signup ran end-to-end into /dashboard. Silent-fail path: auth forms awaited better-auth client with only onSuccess/onError + finally (no catch) — rejected fetch fired no callback. Fix (plan 260828-0742, red-teamed 9 findings, kongming GO): remove VitePWA; ship self-unregistering public/sw.js + dev-sw.js stubs and no-op registerSW.js (clients.claim + includeUncontrolled matchAll + per-client catch); auth forms moved to return-value style with two separated failure layers (auth call vs session verify) using authErrorMessage() guarded reads; e2e: no-service-worker.spec (serviceWorkers allow, behavioral register->drain test) + auth-fail-loudly.spec (CORS-fulfilled routes, distinct toast copy); deploy-staging.yml gains signup->get-session smoke (run_id+run_attempt email, openssl password, 429 retry) and /sw.js + /registerSW.js serving+cache-header asserts on staging and prod (no prod signup smoke — no junk rows). Local Node 20 cannot build apps/server (tsdown needs optional peer unrun for TS configs pre Node 23 native TS); pre-existing on clean develop, CI runs Node 24.
